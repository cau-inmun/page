# 중앙대학교 인문대학 제15대 학생회 ‘연’ 공식 페이지

링크트리를 대신하는 학생회 공식 페이지입니다. **공지 업로드**와 **신청 · 건의 폼 접수**가 중심 기능입니다.

- 화면은 **정적 사이트** (GitHub Pages 무료 호스팅), 데이터는 **Firebase** 가 맡습니다.
- 빌드 도구가 없습니다. 파일을 고쳐 커밋하면 그대로 반영됩니다.
- 핵심 컬러: **`#F8E9D4` 샌드베이지**

---

## 1. 두 가지 동작 모드

| | 미리보기 모드 | 정식 운영 |
| --- | --- | --- |
| 조건 | Firebase 설정이 비어 있음 | `js/firebase-config.js` 를 채움 |
| 공지 | `data/notices.json` 파일 | Firestore (관리자 페이지에서 바로 등록) |
| 링크 | `js/config.js` 기본값 | Firestore (관리자 페이지에서 편집) |
| 폼 제출 | **저장 안 됨** (내 브라우저에만) | Firestore 에 접수 |
| 관리자 로그인 | 없음 (누구나 열람) | 이메일 · 비밀번호 로그인 |

지금 이 저장소는 **미리보기 모드**입니다. 화면과 기능을 그대로 둘러볼 수 있지만,
**실제로 학우들의 신청을 받으려면 아래 3번의 Firebase 연결이 반드시 필요합니다.**

## 3. Firebase 연결하기 (최초 1회, 약 15분)

> ### ⚠ Realtime Database 가 아니라 **Firestore** 입니다
>
> Firebase 에는 데이터베이스가 두 종류 있습니다.
>
> | | Realtime Database | **Cloud Firestore** ← 이 사이트가 쓰는 것 |
> | --- | --- | --- |
> | 주소 모양 | `...-default-rtdb.<리전>.firebasedatabase.app` | 주소 없음 (프로젝트 ID 로 접속) |
> | 콘솔 메뉴 | 빌드 → Realtime Database | 빌드 → **Firestore Database** |
>
> 둘은 이름만 비슷하고 완전히 다른 제품이라 **서로 호환되지 않습니다.**
> Realtime Database 를 이미 만들었더라도 그냥 두고, **Firestore 를 따로 만드세요.**
> (같은 프로젝트에 둘 다 있어도 문제없고, 안 쓰는 쪽은 요금도 들지 않습니다.)
>
> **왜 Firestore 인가** — 예약 공지를 발표 전까지 감추려면 ‘문서 한 건마다’ 읽기를
> 막아야 합니다. Firestore 는 보안 규칙에서 문서의 `publishAt` 을 현재 시각과
> 비교해 차단할 수 있지만, Realtime Database 는 노드 단위로만 허용/차단이 되어
> 목록을 읽을 수 있으면 예약분까지 전부 읽힙니다. 발표 전 공지가 새는 걸
> 막을 수 없어서 Firestore 를 씁니다.

### 3-1. 프로젝트 만들기

1. <https://console.firebase.google.com> → **프로젝트 추가**
2. 이름은 아무거나 (예: `cau-inmun`). Google 애널리틱스는 꺼도 됩니다.

### 3-2. 웹 앱 등록 → 설정 붙여넣기 — ✅ 완료

`js/firebase-config.js` 에 프로젝트 `cau-inmun` 의 설정이 이미 들어가 있습니다.
프로젝트를 새로 만들지 않는 한 이 단계는 다시 할 필요가 없습니다.

> 이 값들은 **비밀이 아닙니다.** 웹 앱에 공개되는 게 정상이고,
> 실제 보안은 다음 단계의 보안 규칙이 담당합니다.

### 3-3. Firestore 만들기

**빌드 → Firestore Database → 데이터베이스 만들기** → **프로덕션 모드**로 시작
→ 위치는 `asia-northeast3 (서울)` 권장.

(Realtime Database 를 만들었더라도 이 단계는 따로 해야 합니다.)

### 3-4. 보안 규칙 배포 ⚠ 가장 중요

**Firestore Database → 규칙** 탭을 열고, 이 저장소의 **`firestore.rules`** 내용을
통째로 붙여넣은 뒤 **게시**하세요.

이 단계를 건너뛰면 **학우들이 제출한 이름 · 학번 · 연락처가 누구에게나 보일 수 있습니다.**

규칙이 하는 일:
- 폼 제출(create)은 누구나 가능하되, 형식을 검증하고 **열려 있는 폼에만** 접수
- 제출 내용 **읽기 · 수정 · 삭제는 관리자만**
- 공지 · 링크 · 폼 정의는 누구나 읽고, 관리자만 수정

### 3-5. 관리자 계정 만들기

1. **빌드 → Authentication → 시작하기** → **이메일/비밀번호** 사용 설정
2. **Users** 탭 → **사용자 추가** → 학생회 공용 이메일과 비밀번호 입력
3. 만들어진 사용자의 **UID** 를 복사합니다.
4. **Firestore Database → 데이터** 탭에서
   - 컬렉션 ID `admins` 로 컬렉션 시작
   - 문서 ID 에 방금 복사한 **UID** 를 붙여넣기
   - 필드는 없어도 됩니다 (아무 필드나 하나 넣어도 무방)
5. 관리자를 늘리려면 2~4 를 반복하세요.

### 3-6-1. (선택) API 키 사용처 제한

`js/firebase-config.js` 의 값은 **비밀이 아닙니다.** Firebase 웹 앱은 설계상 이 설정을
브라우저에 그대로 내려보내므로, 누구나 개발자도구로 볼 수 있고 공개 저장소에 두는 것이 정상입니다.
실제 보안은 `firestore.rules` 가 담당합니다.

다만 다른 사이트가 이 키로 우리 프로젝트에 요청을 보내는 것까지 막고 싶다면,
Google Cloud 콘솔에서 사용처를 제한할 수 있습니다.

1. <https://console.cloud.google.com/apis/credentials> → 프로젝트 `cau-inmun` 선택
2. **Browser key (auto created by Firebase)** 클릭
3. **애플리케이션 제한사항** → **HTTP 리퍼러(웹사이트)** 선택
4. 아래 두 개를 추가
   - `https://cau-inmun.github.io/*`
   - `http://localhost:*` (로컬 확인용)

> 급하지 않습니다. 규칙만 제대로 배포돼 있으면 데이터는 안전합니다.
> 제한을 잘못 걸면 사이트가 아예 안 되므로, 먼저 정상 동작을 확인한 뒤에 하세요.

### 3-6. 도메인 허용

**Authentication → Settings → 승인된 도메인**에
`cau-inmun.github.io` (실제 배포 주소)를 추가합니다. 없으면 로그인이 막힙니다.

### 3-7. 확인 — `setup.html`

**`setup.html`** 을 열면 어디까지 됐는지 항목별로 점검해 줍니다.

```
✓ 1. 설정값 입력
✓ 2. Firebase SDK 불러오기
✕ 3. Firestore 연결        ← 여기서 막히면 3-3 을 안 한 것
  해야 할 일 — Firestore Database 를 아직 만들지 않았을 가능성이 큽니다…
```

✕ 표시된 항목의 **‘해야 할 일’** 만 따라 하면 됩니다.
로그인까지 하면 내 계정 UID 도 보여주므로, 3-5 의 `admins` 등록에 그대로 쓰면 됩니다.

전부 ✓ 가 되면 `admin.html` 에서 바로 관리할 수 있습니다.

### 3-8. 기본 폼을 서버에 올리기 ← 빠뜨리기 쉬움

연결 직후에는 Firestore 에 폼이 하나도 없습니다. 보안 규칙이 ‘Firestore 에 실제로
존재하는 폼’ 에만 제출을 허용하므로, 이 상태에서는 접수가 되지 않습니다.

관리자 → **폼 설정** → 맨 아래 **‘폼 설정 저장’** 을 한 번 누르세요.
기본 폼들이 서버에 등록되면서 접수가 시작됩니다.

그 전까지 학우에게는 폼 대신 **‘아직 접수 준비 중입니다’** 가 보입니다.
(폼을 다 채운 뒤에야 거부당하는 일이 없도록 화면에서 미리 막아둡니다.
브라우저 콘솔에도 원인과 조치가 찍힙니다.)

> 로그인은 되는데 **‘관리자로 등록되지 않은 계정입니다’** 가 뜬다면,
> 3-5 의 `admins` 등록이 빠진 것입니다. 화면에 뜬 UID 를 복사해
> Firestore 의 `admins` 컬렉션에 문서 ID 로 넣으면 됩니다.

`admin.html` 하나로 전부 처리합니다.

### 공지 올리기

**공지** 탭 → 제목 · 분류 · 날짜 · 내용 입력 → 미리보기 확인 → **공지 올리기**.
Firebase 가 연결돼 있으면 그 즉시 사이트에 반영됩니다.

본문에서 쓸 수 있는 문법:

| 입력 | 결과 |
| --- | --- |
| `## 소제목` | 소제목 |
| `- 항목` | 목록 |
| `1. 항목` | 번호 목록 |

포스터 이미지는 `assets/` 에 올린 뒤 **이미지 주소** 칸에 `assets/파일이름.jpg` 를 적으면 됩니다.

### 예약 게시와 보관

공지와 폼 모두 **시각을 정해두면 그때 자동으로 올라가고 내려갑니다.**

| | 비워두면 | 시각을 정하면 |
| --- | --- | --- |
| 공지 · 올라가는 시각 | 지금 바로 게시 | 그 시각부터 공개 |
| 공지 · 내려가는 시각 | 계속 게시 | 그 시각에 **보관**으로 이동 |
| 폼 · 접수 시작 | ‘접수 허용’ 체크대로 | 그 시각부터 접수 |
| 폼 · 접수 마감 | 계속 접수 | 그 시각에 자동 마감 |

**내려간 공지는 삭제되지 않습니다.** 공지사항 페이지의 **‘지난 공지’** 로 옮겨져
학우들이 계속 찾아볼 수 있습니다. 관리자 목록에서 **‘다시 게시’** 를 누르면 되돌릴 수 있고,
반대로 **‘보관’** 을 누르면 예정 시각과 관계없이 지금 바로 내릴 수 있습니다.

관리자 목록에는 상태가 `예약` · `보관` 배지로 표시되고,
맨 위에 `게시 중 n · 예약 n · 보관 n` 으로 집계됩니다.

#### 작동 방식과 한계

이 사이트에는 정해진 시각에 도는 서버 작업(크론)이 없습니다. 대신 **누군가 페이지를 열 때
그 시점을 기준으로 판정**합니다. 그래서:

- 예약한 시각이 지나면 **다음에 페이지를 여는 사람부터** 바로 새 상태로 보입니다.
  따로 배포하거나 버튼을 누를 필요가 없습니다.
- 이미 페이지를 열어둔 사람의 화면은 새로고침 전까지 바뀌지 않습니다.
  다만 폼은 **제출 직전에 한 번 더 확인**하고, 마감된 뒤에는 서버가 거부하므로
  마감 후 제출이 들어오는 일은 없습니다.

> **예약 공지는 완전한 비밀이 아닙니다.**
> 서버에서 도는 스케줄러가 없으면 ‘정해진 시각에 자동 공개’ 와 ‘공개 전 서버 차단’ 을
> 동시에 만족시킬 수 없습니다. 누군가 그 시각에 값을 바꿔줘야 하는데, 정적 사이트에는
> 그럴 주체가 없기 때문입니다. 이 사이트는 **자동 공개** 쪽을 택했습니다.
> 예약 공지는 화면에서 가려지지만, Firestore 를 직접 조회할 줄 아는 사람에게는 보일 수
> 있습니다. 미리 새면 곤란한 내용은 예약해두지 말고 때가 되었을 때 작성해 올리세요.

### 폼 응답 확인

**폼 응답** 탭 → 폼 선택 → 표로 확인. **CSV 내려받기**로 엑셀에서 열 수 있습니다.

> 응답에는 이름 · 학번 · 연락처가 담깁니다. 내려받은 파일은 학생회 내부에서만 다루고,
> 사업이 끝나면 파일과 Firestore 양쪽에서 지워주세요.

### 구글 시트로 응답 받기 (선택)

구글폼처럼 **응답이 스프레드시트에 자동으로 쌓이게** 할 수 있습니다.
Firestore 에도 그대로 저장되므로, 시트는 보기 편하라고 하나 더 두는 것입니다.

1. 구글 드라이브에서 **새 스프레드시트**를 만듭니다.
2. 그 시트의 상단 메뉴 **확장 프로그램 → Apps Script**
   (script.google.com 에서 따로 만들면 시트와 연결되지 않아 아무것도 쌓이지 않습니다.
   이미 그렇게 만들었다면 코드 위쪽 `SHEET_ID` 에 시트 ID 를 넣어주세요)
3. 기본 코드를 지우고, 저장소의 **`docs/google-sheet-webhook.gs`** 내용을 붙여넣습니다.
4. 오른쪽 위 **배포 → 새 배포** → 유형 **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
   - **배포** → 권한 승인
5. 나오는 **웹 앱 URL** (`https://script.google.com/macros/s/…/exec`) 를 복사합니다.
6. `js/firebase-config.js` 가 아니라 **`js/config.js`** 의 `sheetWebhookUrl` 에 붙여넣고 커밋합니다.
   (이미 연결돼 있습니다. 시트를 새로 만들 때만 이 주소를 바꾸면 됩니다)

```js
sheetWebhookUrl: 'https://script.google.com/macros/s/AKfyc.../exec',
```

이제 폼이 제출될 때마다 시트에 한 줄씩 쌓입니다.
**폼마다 탭이 자동으로 생기고**, 관리자에서 항목을 추가하면 열도 자동으로 늘어납니다.
열 이름은 학우가 화면에서 본 **항목 이름**이 그대로 들어갑니다.
(관리자에서 항목 이름을 바꾸면 시트에는 새 열이 생깁니다)

#### 스크립트 코드를 고쳤을 때

**주소를 그대로 두고** 내용만 바꾸려면 —
**배포 → 배포 관리 → 연필(수정) → 버전 ‘새 버전’ → 배포**

‘새 배포’ 를 누르면 **주소가 새로 생깁니다.** 그러면 `js/config.js` 도 같이 고쳐야 하고,
안 고치면 사이트는 예전 주소로 계속 보내서 시트에 아무것도 안 쌓입니다.

#### 시트에 안 쌓일 때

관리자 → **폼 응답** 탭 → **구글 시트 연결 확인** 을 누르세요.
확인용 줄을 한 줄 남겨보고, 안 되면 **무엇이 문제인지 화면에 적어줍니다.**

| 화면에 뜨는 말 | 뜻과 할 일 |
| --- | --- |
| 연결됐습니다 | 정상. 시트에 ‘연결 확인’ 탭이 생겼는지 보세요 |
| 시트에 쓰지 못했습니다 | 스크립트는 도는데 시트를 못 찾음. 시트 메뉴에서 만든 스크립트인지 확인하거나 `SHEET_ID` 를 넣으세요 |
| 답이 오지 않았습니다 | 배포 액세스 권한이 ‘모든 사용자’ 가 아니거나, 고친 코드를 다시 배포하지 않음 |
| 닿지 못했습니다 | 주소가 틀렸거나 `…/exec` 로 끝나지 않음 |
| 주소가 비어 있습니다 | `js/config.js` 의 `sheetWebhookUrl` 이 비어 있음 |

> 제출은 응답을 읽을 수 없는 방식(no-cors)으로 보냅니다. 그래서 학우가 제출할 때는
> 시트가 실패해도 아무 표시가 나지 않습니다. 이 확인 버튼은 읽을 수 있는 방식으로
> 따로 물어보기 때문에 실제 원인을 알 수 있습니다.

> **시트가 실패해도 접수는 정상 처리됩니다.** 정본은 Firestore 이고 시트는 사본이라,
> 시트 쪽 문제로 학우가 두 번 쓰는 일이 없도록 만들었습니다.
>
> ‘액세스 권한: 모든 사용자’ 는 **이 스크립트로 쓰기만** 허용하는 것이고,
> 시트 자체가 공개되는 게 아닙니다. 시트 공유 설정은 그대로 비공개입니다.
>
> 다만 이 주소는 사이트 코드에 들어가므로 누구나 볼 수 있고, 마음먹으면
> 시트에 아무 줄이나 넣을 수 있습니다. 구글폼도 같은 성격이라 큰 문제는
> 아니지만, **정본은 Firestore 이고 시트는 보기 편하라고 두는 사본**이라는
> 점은 알고 계세요. 이상한 줄이 들어오면 시트에서 지우면 되고, 심하면
> Apps Script 배포를 지웠다 새로 만들어 주소를 바꾸면 됩니다.

### 폼 만들고 여닫기

**폼 설정** 탭에서 항목을 추가 · 삭제합니다. 각 폼에는 **기간이 두 개** 있습니다.

| | 무엇을 정하나 | 지났을 때 |
| --- | --- | --- |
| **게시 기간** (`게시 시작` · `게시 종료`) | 폼이 **사이트에 보이는지** | 신청 목록에서 사라지고 **아카이브 탭으로 들어갑니다** |
| **접수 기간** (`접수 시작` · `접수 마감`) | 폼이 **응답을 받는지** | ‘접수가 마감되었습니다’ 로 바뀌고 아카이브에 들어갑니다 |

둘은 따로 놉니다. **게시는 됐는데 접수는 아직 전**(예고용으로 미리 올려두기),
**게시 중인데 접수만 마감**(결과 안내를 위해 남겨두기) 같은 조합이 가능합니다.
다만 **게시 중이 아니면 접수도 받지 않습니다** — 안 보이는 폼이 응답을 받는 일은 없습니다.

- 시각을 비워두면 그 방향으로는 제한이 없습니다 (계속 게시 · 계속 접수)
- **‘사이트에 게시’** 체크를 끄면 시각과 상관없이 **지금 바로** 내려갑니다
- **‘접수 허용’** 체크를 끄면 게시는 그대로 두고 접수만 닫습니다
- 폼 카드 아래에 **게시 : … / 접수 : …** 두 줄로 지금 상태가 표시됩니다

**게시 전인 폼은 주소를 알아도 열리지 않습니다.** 공지의 예약과 같은 규칙입니다.
접수 마감과 게시 종료는 화면뿐 아니라 **보안 규칙이 서버에서도 제출을 막습니다.**

각 폼의 공개 주소는 `apply.html?id=폼아이디` 입니다. 인스타 프로필이나 공지에 이 주소를 쓰세요.

> **홈의 ‘링크 모음’ 은 따로 관리됩니다.** 게시 예약해둔 폼의 링크를 미리 걸어두면
> 게시 시각 전까지는 눌러도 ‘폼을 찾을 수 없습니다’ 가 뜹니다.
> 링크는 **게시가 시작된 뒤** 링크 탭에서 추가하세요.
>
> 예약해둔 폼의 제목과 항목은 Firestore 를 직접 조회할 줄 아는 사람에게는 보일 수
> 있습니다 (공지 예약과 같은 이유 — 서버 스케줄러가 없기 때문). 미리 새면 곤란한
> 내용은 예약해두지 말고 때가 되었을 때 만드세요.

### 링크 추가

**링크** 탭에서 묶음과 버튼을 추가 · 순서 변경 · 삭제하고 **링크 저장**.
주소를 비워두면 홈에 ‘준비 중’ 으로 표시됩니다.

### 지난 것 찾아보기 (아카이브)

**아카이브** 탭에서 게시가 끝난 공지와 폼을 모아 봅니다.

- **지난 공지** : 제목을 누르면 학우에게 보이는 화면이 새 창에서 열립니다.
  ‘다시 게시’ 로 되살리거나 완전히 지울 수 있습니다.
- **지난 폼** : 게시가 끝났거나 접수가 마감된 폼입니다. 어느 쪽인지는
  **‘게시 끝’ · ‘마감’** 표시로 구분합니다. ‘응답 보기’ 로 그 폼의 접수 내역으로
  바로 이동하고, **‘다시 게시’ · ‘다시 열기’** 로 되살릴 수 있습니다.

지난 공지는 삭제된 것이 아니라 공지사항 페이지의 ‘지난 공지’ 에서
학우들도 계속 찾아볼 수 있습니다.

### 사이트 정보 바꾸기

**사이트 정보** 탭에서 아래를 코드 수정 없이 바꿉니다.

- 대학 이름 · 기수 · 학생회 이름 · 한 줄 소개 · 공유 미리보기 문구
- 상단 빠른 버튼 (인스타그램 · 카카오톡 채널 등)
- 학생회 소개 글과 국(부서) 구성
- 푸터 주소 · 인스타그램 · 카카오톡 채널 · 이메일
- 공지 분류, 폼의 학과 선택지, 개인정보 동의 문구

저장하면 홈 제목 · 브라우저 탭 제목 · 푸터에 함께 반영됩니다.

> 학생회가 바뀌어도 **‘제16대 학생회’ · 새 이름** 만 여기서 고치면 됩니다.
> 코드를 건드릴 일은 로고 파일 교체 정도입니다.

## 6. 글꼴

사이트 전체가 애플의 **San Francisco** 를 씁니다. 제목과 본문이 같은 글꼴이고
굵기와 크기로만 구분합니다 (애플 자사 페이지와 같은 방식).

| 보는 기기 | 실제로 쓰이는 글꼴 |
| --- | --- |
| 맥 · 아이폰 · 아이패드 | **San Francisco** (한글은 Apple SD Gothic Neo) — 운영체제가 가진 것 |
| 윈도우 · 안드로이드 | **프리텐다드 Pretendard** (OFL, 상업적 이용 무료) |

### SF 파일을 직접 넣지 않은 이유

애플 개발자 사이트에서 받는 SF Pro 는 **웹사이트에 심을 수 없습니다.**

1. **라이선스** — 애플 플랫폼용 앱과 그 목업에만 쓰도록 제한되어 있고,
   웹폰트로 배포하는 것은 허용되지 않습니다. 학생회 공식 사이트라 더욱
   문제 소지를 남기지 않는 편이 낫습니다.
2. **한글이 없습니다** — SF Pro 에는 한글 글자가 들어 있지 않습니다.
   이 사이트는 거의 전부 한글이라, 심어도 대부분의 글자에 적용되지 않습니다.
   애플의 한글 글꼴 Apple SD Gothic Neo 는 그 배포 대상이 아닙니다.

그래서 **애플 기기에서는 운영체제에 이미 있는 SF 를 그대로 부르고**(이건
라이선스 문제가 없습니다 — 파일을 배포하는 게 아니라 그 기기의 글꼴을 쓰는
것이므로), 다른 환경에서는 **프리텐다드**로 대신합니다. 프리텐다드는 애플
시스템 글꼴을 다른 환경에서 쓰려고 만든 글꼴이라 인상이 거의 같습니다.

### 어디를 고치나

순서는 `css/style.css` 의 **`--font-sf`** 한 줄에 모여 있고,
`--font-body` · `--font-display` 가 그것을 가리킵니다.
실제로 내려받는 것은 `css/fonts.css` 의 프리텐다드뿐입니다.

프리텐다드는 **가변 글꼴 + 동적 서브셋**이라 실제로 쓰인 글자만 내려받습니다.
굵기 45~920 을 파일 하나로 처리하므로 용량 부담이 적습니다.

### 제목을 페이퍼로지로 되돌리려면

`css/style.css` 에서 한 줄만 바꾸면 됩니다. `@font-face` 는 `css/fonts.css` 에
그대로 남겨두었습니다 (쓰이지 않으면 내려받지 않으므로 느려지지 않습니다).

```css
--font-display: 'Paperlogy', var(--font-sf);
```

### 글꼴이 안 보일 때

맥 · 아이폰에서는 운영체제 글꼴이라 이런 일이 없습니다.
윈도우 · 안드로이드에서 프리텐다드를 못 받은 경우입니다.

1. **F12 → Console** 에서 `[글꼴] 불러오지 못했습니다: …` 경고를 확인합니다.
2. <https://github.com/orioncactus/pretendard> 의 최신 코드로
   `css/fonts.css` 의 블록을 교체합니다.

못 불러와도 시스템 한글 글꼴로 정상 표시되므로 화면이 깨지지는 않습니다.

## 8. 자주 묻는 것

**Q. `admin.html` 을 아무나 볼 수 있는 것 아닌가요?**
Firebase 를 연결하면 로그인 화면이 막습니다. 로그인해도 `admins` 에 등록된 UID 가 아니면
보안 규칙이 서버에서 데이터를 거부합니다. 화면 접근과 데이터 접근이 이중으로 막혀 있습니다.
(미리보기 모드에서는 로그인이 없지만, 그때는 저장되는 실제 데이터도 없습니다.)

**Q. 폼 제출이 안 됩니다.**
**`setup.html`** 을 여세요. 어디서 막혔는지 항목별로 짚어줍니다.
가장 흔한 원인은 ③ **폼 설정 저장을 안 눌러 서버에 폼이 없는 경우**(3-8),
그리고 ② **`firestore.rules` 미배포**(3-4) 입니다.

**Q. Realtime Database 를 만들었는데 왜 안 되나요?**
이 사이트는 **Firestore** 를 씁니다. 이름이 비슷하지만 다른 제품입니다.
3장 맨 위 설명을 보고 **Firestore Database** 를 따로 만드세요.
Realtime Database 는 지우지 않아도 되고, 안 쓰면 요금도 들지 않습니다.

**Q. 스팸이 들어오면요?**
숨김 필드로 단순 봇은 거르고, 보안 규칙이 필드 개수와 형식을 제한합니다.
그래도 사람이 반복 제출하는 것은 막지 못하므로, 문제가 생기면
**폼 설정**에서 접수를 잠시 닫고 Firebase 콘솔에서 정리하세요.

**Q. 공지 순서를 바꾸고 싶어요.**
최신 날짜 순으로 자동 정렬됩니다. 맨 위에 두려면 **‘목록 맨 위에 고정하기’** 를 켜세요.

**Q. 예약해둔 공지가 시간이 지나도 안 올라와요.**
누군가 페이지를 열어야 판정이 이뤄집니다. 직접 새로고침해 보세요.
그래도 안 보이면 관리자 목록에서 그 공지의 상태 배지가 아직 `예약` 인지,
올라가는 시각이 의도한 대로인지 확인하세요. 시각은 **보는 사람의 기기 시각** 기준입니다.

**Q. 지난 공지를 완전히 지우려면요?**
관리자 목록의 **삭제** 를 쓰세요. **보관** 은 지우는 게 아니라 ‘지난 공지’ 로 옮기는 것입니다.

**Q. Firebase 가 안 될 때 사이트가 멈추나요?**
아닙니다. 8초 안에 연결되지 않으면 저장소 파일로 자동 전환합니다.
공지는 `data/notices.json`, 링크는 `js/config.js` 값이 보이고 폼 제출만 막힙니다.
브라우저 콘솔(F12)에 원인과 함께 안내가 찍힙니다.

**Q. Firebase 요금이 나오나요?**
학생회 규모(하루 수백 건 읽기·쓰기)는 무료 Spark 요금제 한도 안에 충분히 들어갑니다.
걱정되면 Firebase 콘솔에서 예산 알림을 걸어두세요.

## 9. 접근성 · 호환성

- 모바일 우선. 320px 부터 데스크톱까지 가로 스크롤 없이 동작합니다.
- 키보드 탐색, 건너뛰기 링크, 스크린리더용 레이블을 넣었습니다.
- 폼 오류는 `role="alert"` 로 안내하고, 첫 오류 항목으로 포커스를 옮깁니다.
- 애니메이션은 `prefers-reduced-motion` 설정을 따릅니다.
- 웹폰트는 `font-display: swap` 이라 글꼴 로딩이 본문 표시를 막지 않습니다.
