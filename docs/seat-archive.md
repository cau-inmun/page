# 열람실 일자별 이용 내역

관리자 → 열람실 좌석 → 날짜 선택 → 엑셀 내려받기 (.xlsx).
한국 시간 기준으로 일자를 구분합니다. 자정에는 새 날짜의 좌석표를 사용하며 지난 날짜의 이력은 삭제하지 않습니다.

## 적용

1. Firebase Console → Firestore Database → 규칙에서 저장소의 `firestore.rules` 전체를 붙여넣고 게시합니다.
2. 관리자 열람실 화면을 새로고침합니다. 규칙 미적용 경고가 없어지는지 확인합니다.
3. 테스트 예약 → 자리 변경 → 반납을 하고 해당 날짜의 이용 내역과 엑셀을 확인합니다.

규칙을 게시하기 전에도 기존 예약/반납은 계속 동작합니다. 다만 새 누적 이력 저장이 거절되므로 완전한 아카이브는 규칙 게시 후부터 시작됩니다. 기존 브라우저 탭도 새로고침해야 새 기록 방식이 적용됩니다. 관리자 화면은 규칙이 미적용이면 경고하고 남아 있는 기존 기록만 보여 줍니다.

## 저장 방식

- `seatdays/{YYYY-MM-DD}/events/{자동 ID}`: 관리자만 읽을 수 있는 추가 전용 이력. 예약, 변경 전 해제, 변경 후 예약, 반납, 취소, 관리자 취소를 구분합니다.
- 예약·반납과 이력 저장은 새 규칙에서 동일한 배치로 처리합니다. 관리자 취소는 트랜잭션으로 저장합니다.
- 자리 변경은 기존 기능과 같이 두 단계입니다. 기존 자리를 비운 뒤 새 예약 전에 중단하면 해제 기록만 남습니다. 새 예약 행에는 이전 좌석 번호가 표시됩니다.
- 날짜 선택 시 남아 있는 기존 `logs` / `releases`도 합쳐 표시하며 새 이력과 중복되는 행은 제외합니다. 기능 도입 전에 삭제·덮어쓴 기록은 복원할 수 없습니다. 예전 `cancel` 기록은 취소/변경으로 표시합니다.
- 엑셀은 이용 내역, 남아 있는 예약, 안내의 3개 시트입니다. 시각은 한국 시간이고 모든 셀을 텍스트로 저장해 학번·전화번호 앞자리 0과 수식 형태의 사용자 입력을 보존합니다.
- 파일 생성 코드는 관리자 다운로드 시에만 불러옵니다. 외부 엑셀 라이브러리를 공개 페이지에 추가하지 않습니다.

## 점검

```sh
node docs/check-firestore-rules.js
node docs/test-seat-archive.cjs
```

규칙 점검 스크립트는 함수 참조 검사입니다. 서버에 규칙을 게시하는 기능은 없습니다.

보안 규칙 회귀 테스트는 `firebase-tools`, `firebase`, `@firebase/rules-unit-testing`과 로컬 Firestore 에뮬레이터가 필요합니다. 테스트 프로젝트는 운영과 분리된 `demo-cau-archive`로 고정됩니다.

```sh
FIRESTORE_EMULATOR_HOST=127.0.0.1:8787 node docs/test-seat-rules.cjs
```

실제 저장 함수를 통해 예약/변경/반납/관리자 취소가 이력과 함께 저장되는지, 중복 예약/잘못된 본인 확인/비관리자 이력 조회/이력 수정·삭제/허위 이력 생성이 차단되는지 검사합니다.
